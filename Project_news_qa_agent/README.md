# AI News Q&A Agent

관심 주제에 대한 최근 뉴스를 수집하고, **수집된 기사 범위 안에서 근거를 들어 답변하는 RAG 기반 뉴스 Q&A 에이전트**입니다.

프로그램 시작 시 뉴스를 한 번 수집하고 정제한 뒤 FAISS 인메모리 벡터스토어를 구축합니다. 이후 질문은 추가 크롤링 없이 세션에 저장된 기사에서 관련 근거를 검색해 처리합니다.

```text
관심 분야를 입력하세요: 강남
검증 키워드를 입력하세요: 방송인
기간을 숫자로 입력하세요: 30

[1/7] 주제 분석 완료
[2/7] 제외 키워드 자동 생성 완료
[3/7] 뉴스 검색 완료
[4/7] 본문 크롤링 완료
[5/7] 중복 제거 완료
[6/7] 관련성 필터 완료
[7/7] 인메모리 벡터스토어 구축 완료

질문> 강남은 최근 어떤 방송에 출연했어?
```

---

## 프로젝트 목표

일반적인 LLM은 최신 이슈에 답하기 어렵거나, 충분한 근거 없이 사실처럼 보이는 답변을 생성할 수 있습니다.

이 프로젝트는 사용자가 지정한 기간의 뉴스를 실시간으로 수집하고, 수집된 기사만 답변 근거로 사용하도록 설계했습니다.

답변에는 `(기사 N)` 형식으로 출처를 표시하며, 기사 데이터와 벡터스토어는 별도 데이터베이스에 저장하지 않고 실행 중인 세션 동안만 메모리에 유지합니다.

뉴스 검색 과정에서 발생할 수 있는 다음 문제를 해결하는 데 초점을 맞췄습니다.

* 약어, 영문명, 정식 명칭 등 표기 차이로 인한 검색 누락
* 동음이의어나 유사 명칭으로 인한 무관 기사 유입
* 동일한 내용을 반복 보도한 중복 기사
* 질문과 기사 본문의 표현 차이로 인한 검색 실패
* 기사 근거 없이 생성되는 환각성 답변

---

## 핵심 기능

### 1. 관심 분야와 검증 키워드 분리

사용자는 검색할 관심 분야와 검색 범위를 좁히는 검증 키워드를 별도로 입력합니다.

```text
관심 분야: 강남
검증 키워드: 방송인
```

두 입력값은 서로 다른 역할을 수행합니다.

* **관심 분야**: 뉴스 검색 키워드 생성의 기준
* **검증 키워드**: 관심 분야와 결합해 뉴스 검색 쿼리를 구체화하는 기준

예를 들어 `강남`만 검색하면 지역, 부동산, 상권, 학원 관련 기사가 다수 포함될 수 있습니다.

이때 `방송인`을 검증 키워드로 입력하면 다음과 같은 조합 쿼리를 우선 검색해 처음부터 노이즈가 적은 검색 결과를 수집합니다.

```text
강남 방송인
연예인 강남 방송인
```

검증 키워드는 관련성 필터에서 기사를 제거하는 기준으로 사용하지 않습니다. 뉴스 검색 API를 호출하는 단계에서 검색 범위를 좁히는 용도로만 사용합니다.

---

### 2. 뉴스 검색 키워드 자동 생성

사용자가 입력한 관심 분야를 그대로 검색하면 정식 명칭, 약어, 영문 표기 등의 차이로 일부 기사를 놓칠 수 있습니다.

LLM은 관심 분야를 분석해 뉴스 검색에 사용할 키워드 후보를 생성합니다.

생성 기준은 다음과 같습니다.

* 사용자가 입력한 원문을 검색 키워드에 유지
* 확실한 경우에만 정식 명칭, 약어, 영문 표기 추가
* 최대 4개의 검색 키워드 생성

예시는 다음과 같습니다.

```text
입력: 서울여대
출력: ["서울여대", "서울여자대학교", "SWU"]
```

생성된 검색 키워드는 사용자가 입력한 검증 키워드와 조합되어 뉴스 검색 API에 전달됩니다.

LLM이 정해진 JSON 형식을 지키지 못하거나 분석에 실패하면, 사용자가 입력한 원문을 그대로 검색 키워드로 사용하는 폴백 로직을 적용합니다.

수집 기간은 LLM이 추론하지 않으며, 사용자가 입력한 숫자를 그대로 사용합니다.

---

### 3. 동음이의어 제외 키워드 자동 생성

관심 분야가 여러 의미로 사용되는 경우, 검색 쿼리를 구체화하더라도 일부 무관 기사가 함께 수집될 수 있습니다.

이를 제거하기 위해 LLM이 관심 분야만을 바탕으로 동음이의어와 혼동 개체를 나타내는 제외 키워드를 자동 생성합니다.

예를 들어 관심 분야가 `당근`이고 검증 키워드가 `회사`인 경우 다음과 같이 동작합니다.

```text
관심 분야: 당근
검증 키워드: 회사

검색 단계:
- 당근 회사
- 당근마켓 회사

자동 생성된 제외 키워드:
- 당근 재배
- 당근 농가
- 당근 가격
- 당근 효능
- 당근 요리법
```

검증 키워드는 검색 결과를 좁히고, 제외 키워드는 수집된 기사 중 다른 의미를 다루는 기사를 제거합니다.

```text
검증 키워드
→ 뉴스 검색 단계에서 사용

제외 키워드
→ 기사 수집 이후 관련성 필터 단계에서 사용
```

두 단계는 서로 다른 지점에서 노이즈를 줄이기 때문에 상호 보완적으로 동작합니다.

제외 키워드는 관심 분야 하나당 한 번만 생성하고, 세션 내 모든 기사에 동일하게 적용합니다. 기사마다 제외 키워드를 다시 생성하지 않아 불필요한 LLM 호출을 줄였습니다.

---

### 4. 일반 표현 조합형 주제를 위한 보호 로직

일부 관심 분야는 하나의 고유한 단어가 아니라 여러 일반 표현의 조합으로 이루어져 있습니다.

예를 들어 `서울여대`는 다음과 같은 일반 표현과 일부가 겹칩니다.

```text
서울
여대
여자대학교
대학교
```

이러한 단어를 그대로 제외 기준으로 사용하면 `서울여자대학교`를 실제로 다루는 정상 기사까지 제거될 수 있습니다.

이를 방지하기 위해 제외 키워드 생성 결과 중 관심 분야를 구성하는 일반 표현을 별도로 확인합니다.

기사에서 일반 표현이 발견되더라도, 해당 표현이 관심 분야 전체를 나타내는 문맥으로 사용된 경우에는 관련 기사로 유지합니다.

예시는 다음과 같습니다.

```text
관심 분야: 서울여대

일반 표현:
- 서울
- 여대
- 여자대학교
- 대학교

보호할 표현:
- 서울여대
- 서울여자대학교
```

즉 이 단계는 단순히 관심 분야가 기사에 한 번 등장했는지를 확인하는 것이 아니라, **여러 일반 단어의 조합으로 만들어진 주제가 불완전한 단어 단위 제외 규칙 때문에 제거되지 않도록 보호하는 과정**입니다.

---

### 5. 의미 기반 중복 제거

여러 언론사가 같은 사건이나 보도자료를 유사하게 보도하면 제목이 달라도 사실상 동일한 기사가 반복 수집될 수 있습니다.

각 기사 본문을 임베딩한 뒤 코사인 유사도를 비교하고, 설정된 임계값 이상으로 유사한 기사는 중복 기사로 판단해 대표 기사 하나만 유지합니다.

```text
본문 크롤링 완료 → 94건
중복 제거 완료 → 94건 → 65건
```

단순 제목 비교가 아니라 기사 본문의 의미를 기준으로 판단하기 때문에, 제목이 다르더라도 내용이 유사한 기사를 제거할 수 있습니다.

#### 중복 제거를 관련성 필터보다 먼저 수행하는 이유

현재 파이프라인에서는 중복 제거를 관련성 필터보다 먼저 수행합니다.

동일한 사안을 다룬 유사 기사 여러 건이 있을 때 관련성 필터를 먼저 적용하면, 사실상 같은 내용을 가진 기사에 대해 필터 판정을 반복하게 됩니다.

중복 제거를 먼저 수행하면 대표 기사만 관련성 필터를 통과하므로 다음과 같은 이점이 있습니다.

* 동일 내용에 대한 반복 판정 감소
* 기사 임베딩 재사용
* LLM 경계 판정 호출 감소
* 전체 처리 비용과 실행 시간 절감

기사 임베딩은 한 번만 생성하며, 중복 제거와 관련성 필터에서 함께 재사용합니다.

---

### 6. 제외 키워드 기반 관련성 필터

중복 제거를 통과한 기사에는 자동 생성된 제외 키워드를 적용합니다.

제외 키워드가 기사에서 실제로 다른 의미나 혼동 개체를 나타내는 경우 해당 기사를 제거합니다.

```text
관심 분야: 강남

제외 키워드:
- 강남구
- 강남역
- 강남스타일
- 강남 사무소
- 강남 학원
```

이를 통해 방송인 강남을 검색할 때 지역, 상권, 교통, 학원 관련 기사가 최종 기사 집합에 포함되는 것을 줄입니다.

일반 표현의 조합으로 이루어진 주제에는 앞서 설명한 보호 로직을 함께 적용해 정상 기사 누락을 방지합니다.

---

### 7. FAISS 인메모리 벡터스토어

관련성 필터를 통과한 기사로 FAISS 벡터스토어를 구축합니다.

벡터스토어는 프로그램 실행 중에만 메모리에 유지되며, 세션이 종료되면 기사와 벡터 데이터도 함께 삭제됩니다.

```text
뉴스 수집
→ 본문 크롤링
→ 임베딩
→ 중복 제거
→ 관련성 필터
→ FAISS 벡터스토어 구축
```

하나의 뉴스 수집 세션을 구축한 이후에는 질문할 때마다 뉴스를 다시 크롤링하지 않습니다.

---

### 8. HyDE 기반 기사 검색

질문의 표현과 기사 본문의 표현이 다르면 질문을 그대로 임베딩하는 방식으로는 관련 기사를 찾지 못할 수 있습니다.

HyDE는 질문에 대한 답이 포함되어 있을 법한 가상의 기사 문장을 먼저 생성합니다.

```text
질문:
강남이 아내를 위해 딴 자격증은 뭐야?

가상 기사 문장:
방송인 강남은 아내 이상화를 위해 스포츠 마사지 자격증을 취득했다고 밝혔다.
```

생성된 가상 기사 문장을 임베딩한 뒤 실제 기사 벡터와 비교합니다.

이를 통해 인물, 행사, 사업, 제품 설명처럼 질문과 기사 본문의 표현이 직접 일치하지 않는 경우 의미 기반 검색을 보완합니다.

---

### 9. Multi-Query 검색 실험

Multi-Query는 하나의 질문을 의미가 유사한 여러 표현으로 재구성한 뒤 각각 검색하는 방식입니다.

```text
원 질문:
강남은 최근 어떤 방송에 출연했어?

변형 질문:
- 방송인 강남의 최근 방송 출연작은 무엇인가?
- 강남이 최근 출연한 예능 프로그램은 무엇인가?
- 연예인 강남이 출연한 방송은 무엇인가?
```

프로젝트의 검색 성능 평가에서는 다음 네 가지 조건을 비교했습니다.

* 질문 원문만 검색하는 Base
* HyDE만 적용
* Multi-Query만 적용
* HyDE와 Multi-Query를 함께 적용

현재 기본 질문 처리 흐름은 `retrieve_relevant_articles()`의 기본 검색 설정을 사용합니다.

---

### 10. 임계값 기반 기사 검색

질문마다 항상 같은 개수의 기사를 반환하지 않습니다.

질문과 기사의 코사인 유사도가 `RELEVANCE_SIMILARITY_THRESHOLD` 이상인 기사만 답변 근거 후보로 사용합니다.

`TOP_K_ARTICLES`는 반드시 반환해야 하는 기사 수가 아니라 반환 가능한 최대 기사 수입니다.

```text
TOP_K_ARTICLES: 10
유사도 임계값을 통과한 기사: 3건
최종 반환 기사: 3건
```

관련성이 낮은 기사를 개수에 맞추기 위해 억지로 포함하지 않아 질문과 출처 사이의 연관성을 유지합니다.

---

### 11. 근거 기반 답변과 인라인 인용

검색된 기사만 답변 생성 프롬프트에 전달합니다.

기사에서 확인할 수 있는 내용에는 다음과 같이 출처를 표시합니다.

```text
강남은 최근 MBC 예능 프로그램 ‘라디오스타’에 출연했습니다. (기사 1)
```

답변 하단에는 실제로 사용된 기사의 제목, 언론사, 링크를 제공합니다.

수집된 기사에서 관련 근거를 찾지 못한 경우에는 모델의 일반 지식으로 답을 만들어내지 않고, 현재 수집된 기사 범위에서는 확인할 수 없다고 안내합니다.

---

## 동작 흐름

```text
사용자 입력
   │
   ├─ 관심 분야
   ├─ 검증 키워드
   └─ 수집 기간
   │
   ▼
뉴스 검색 키워드 자동 생성
   │
   ▼
동음이의어 제외 키워드 자동 생성
   │
   ▼
검색 키워드 + 검증 키워드 조합
   │
   ▼
네이버 뉴스 검색 API 호출
   │
   ▼
기사 본문 비동기 크롤링
   │
   ▼
기사 임베딩
   │
   ▼
의미 기반 중복 제거
   │
   ▼
제외 키워드 기반 관련성 필터
   │
   ▼
일반 표현 조합형 주제 보호
   │
   ▼
FAISS 인메모리 벡터스토어 구축
   │
   ▼
사용자 질문
   │
   ▼
HyDE 기반 검색 확장
   │
   ▼
유사도 임계값 기반 기사 검색
   │
   ▼
근거 기반 답변 및 출처 생성
```

세부 실행 단계는 다음과 같습니다.

1. 관심 분야, 검증 키워드, 수집 기간을 입력받습니다.
2. LLM이 관심 분야의 뉴스 검색 키워드를 생성합니다.
3. LLM이 관심 분야와 혼동될 수 있는 제외 키워드를 생성합니다.
4. 검색 키워드와 검증 키워드를 조합해 뉴스 검색 API를 호출합니다.
5. `aiohttp`와 `BeautifulSoup`으로 기사 본문을 비동기로 크롤링합니다.
6. 기사 임베딩을 한 번 생성합니다.
7. 임베딩 유사도를 기준으로 의미적 중복 기사를 제거합니다.
8. 제외 키워드로 동음이의어나 유사 명칭 관련 기사를 필터링합니다.
9. 일반 표현의 조합으로 이루어진 주제의 정상 기사를 보호합니다.
10. 정제된 기사로 FAISS 인메모리 벡터스토어를 구축합니다.
11. 사용자의 질문을 검색에 적합한 형태로 확장합니다.
12. 유사도 임계값을 통과한 기사만 검색합니다.
13. 검색된 기사를 근거로 답변과 출처를 생성합니다.

## 시작하기

### 1. 가상환경 생성

```bash
python -m venv venv
```

Windows:

```bash
venv\Scripts\activate
```

Linux 또는 macOS:

```bash
source venv/bin/activate
```

### 2. 패키지 설치

```bash
pip install -r requirements.txt
```

### 3. 환경변수 설정

`env.example.txt`를 복사해 `.env` 파일을 생성한 뒤 다음 값을 입력합니다.

```env
OPENAI_API_KEY=
NAVER_CLIENT_ID=
NAVER_CLIENT_SECRET=
```

### 4. 실행

완전 인터랙티브 방식:

```bash
python main.py
```

관심 분야만 실행 인자로 전달:

```bash
python main.py "서울여대"
```

관심 분야, 검증 키워드, 기간을 모두 전달:

```bash
python main.py "서울여대" "전공" 7
```

프로그램 시작 시 필수 API 키가 누락됐는지 검사합니다. 누락된 값이 있으면 실행을 중단하고 필요한 환경변수를 안내합니다.

# 성능 평가

프로젝트에서는 다음 두 단계를 별도로 평가했습니다.

1. 수집된 기사에서 무관 기사를 제거하는 **관련성 필터 성능**
2. 정제된 기사에서 질문의 근거를 찾는 **Retrieval 성능**

---

## 관련성 필터 평가

### 평가 조건

다음 세 가지 필터 조건을 비교했습니다.

| 조건 | 설명                            |
| -- | ----------------------------- |
| V0 | 별도의 제외 키워드 필터 없이 모든 기사 유지     |
| V1 | 동음이의어 및 혼동 개체 제외 키워드 적용       |
| V2 | 제외 키워드와 일반 표현 조합형 주제 보호 로직 적용 |

### 평가 데이터

다음 4개 주제에서 수집한 총 338건의 기사에 관련 또는 무관 라벨을 직접 부여했습니다.

| 주제     |    기사 수 | 주요 혼동 유형      |
| ------ | ------: | ------------- |
| 서울여대   |      99 | 일반적인 지역·대학 표현 |
| 강남     |      91 | 방송인과 지역명      |
| 당근     |      60 | 플랫폼과 채소       |
| 제논     |      88 | 기업과 원소·가스·조명  |
| **전체** | **338** |               |

### 평가 결과

| 조건 | Precision |    Recall |  F1-score |  Accuracy |
| -- | --------: | --------: | --------: | --------: |
| V0 |     0.379 | **1.000** |     0.549 |     0.379 |
| V1 | **0.526** |     0.797 |     0.634 | **0.651** |
| V2 |     0.487 | **1.000** | **0.655** |     0.601 |

V1은 동음이의어 제외 키워드를 적용해 무관 기사 유입을 줄였지만, 일반 표현의 조합으로 이루어진 주제에서 일부 관련 기사도 제거했습니다.

V2는 이러한 주제를 위한 보호 로직을 추가해 관련 기사 128건을 모두 유지했습니다.

```text
Precision : 0.379 → 0.487
Recall    : 1.000 → 1.000
F1-score  : 0.549 → 0.655
Accuracy  : 0.379 → 0.601
```

최종 시스템은 관련 기사가 수집 단계에서 사라지지 않도록 Recall을 우선하고, V0보다 무관 기사 비율을 줄인 V2 방식을 적용했습니다.

## Retrieval 검색 성능 평가

### 평가 조건

| 조건          | 설명                       |
| ----------- | ------------------------ |
| Base        | 사용자 질문 원문만 임베딩해 검색       |
| HyDE only   | 질문에 대한 가상의 기사 문장을 생성해 검색 |
| MultiQ only | 질문을 여러 표현으로 재구성해 검색      |
| Both        | HyDE와 Multi-Query를 모두 적용 |

### 평가 방법

다음 4개 주제에서 총 39개의 골든 질문을 구성했습니다.

* **제논**: 대표, 행사, 제품, 서비스 및 사업 방향 관련 질문
* **당근**: 기업과 채소 기사가 혼재하는 동음이의어 주제
* **서울여대**: 기관, 인물, 학과 및 입시 정보 관련 질문
* **강남**: 방송인과 지역명이 동일한 동음이의어 주제

검색된 상위 기사 중 정답을 확인할 수 있는 필수 키워드가 포함된 기사가 하나 이상 존재하면 검색 성공으로 판정했습니다.

이는 생성된 답변의 정확도나 충실도를 측정하는 것이 아니라, 정답의 근거가 되는 기사를 검색했는지를 측정하는 **Retrieval Hit Rate** 평가입니다.

### 평가 결과

| 주제           |   문항 수 |      Base | HyDE only | MultiQ only |      Both |
| ------------ | -----: | --------: | --------: | ----------: | --------: |
| 제논           |     13 |     61.5% | **92.3%** |       69.2% | **92.3%** |
| 당근           |     10 |     50.0% |     40.0% |       50.0% |     50.0% |
| 서울여대         |     10 |     70.0% |     70.0% |       70.0% |     70.0% |
| 강남           |      6 |     66.7% | **83.3%** |   **83.3%** | **83.3%** |
| **Micro 평균** | **39** | **61.5%** | **71.8%** |   **66.7%** | **74.4%** |

주제별 결과를 동일한 비중으로 계산한 Macro 평균은 다음과 같습니다.

| 조건          | Macro Hit Rate |
| ----------- | -------------: |
| Base        |          62.1% |
| HyDE only   |          71.4% |
| MultiQ only |          68.1% |
| Both        |      **73.9%** |

전체 질문 기준 결과는 다음과 같습니다.

```text
Base        : 24/39 (61.5%)
HyDE only   : 28/39 (71.8%)
MultiQ only : 26/39 (66.7%)
Both        : 29/39 (74.4%)
```

HyDE와 Multi-Query를 함께 적용했을 때 Retrieval Hit Rate가 Base의 61.5%에서 74.4%로 **12.9%p 향상**되었습니다.

특히 기업 관련 자연어 질문으로 구성된 제논 주제에서는 HyDE 적용 후 Hit Rate가 61.5%에서 92.3%로 **30.8%p 향상**되었습니다.

강남 주제에서도 Base가 검색하지 못한 근거 기사를 검색하면서 Hit Rate가 66.7%에서 83.3%로 상승했습니다.

반면 당근 주제에서는 HyDE 단독 성능이 Base보다 낮았습니다. 구체적인 서류명이나 기관명처럼 원 질문에 이미 충분한 검색 단서가 포함된 경우, 생성된 가상 기사 문장이 핵심 표현을 약화시킬 수 있음을 확인했습니다.

서울여대처럼 질문과 기사 표현이 이미 잘 일치하는 주제에서는 검색 확장 방식에 따른 성능 차이가 나타나지 않았습니다.

검색 확장 방식은 모든 질문을 일관되게 개선하지는 않았지만, 질문과 기사 사이의 표현 차이가 큰 자연어 질문에서 검색을 보완할 수 있음을 확인했습니다.

> 뉴스 검색 결과는 기사 게시, 삭제, 검색 순위, 크롤링 성공 여부에 따라 달라질 수 있습니다. 본 평가는 2026년 7월 31일에 수집한 최근 50일 이내의 기사를 기준으로 수행했습니다.

## 알려진 이슈

### `httpx proxies` 오류

OpenAI 패키지와 일부 `httpx` 버전의 호환성 문제로 발생할 수 있습니다.

```text
httpx==0.27.2
```

### 네이버 API 401 오류

기존 네이버 개발자센터 API와 NCP API Gateway 방식은 인증 헤더가 다릅니다.

현재 프로젝트는 `X-NCP-APIGW-*` 헤더를 사용하는 NCP 방식으로 구현되어 있습니다.

### 콘솔 한글 입력 오류

PyCharm 콘솔와 한글 IME 조합에서 입력이 누락되거나 깨질 수 있습니다.

UTF-8 입출력 설정과 불완전한 자모 입력 감지 로직을 적용했으며, 문제가 지속되면 실행 인자로 관심 분야, 검증어, 기간을 전달할 수 있습니다.

```bash
python main.py "서울여대" "전공" 7
```

### 실행 시점에 따른 평가 결과 변화

뉴스 검색 결과는 새로운 기사 게시, 기존 기사 삭제, 검색 순위 변경, 언론사 페이지 구조 및 본문 크롤링 성공 여부에 따라 달라질 수 있습니다.

평가 결과를 비교할 때는 실행 날짜, 관심 분야, 검증 키워드, 수집 기간을 함께 기록하는 것이 좋습니다.
